## Intent

**Problem:** `ezop` still carries the inherited GoReleaser publishers (`nfpms`, `aurs`, `homebrew_casks`, `winget`), four Upstream workflows that can publish or commit, and `release` settings (`mode: replace`, `replace_existing_artifacts: true`) that let a repeat run overwrite a release's files. Nothing checks the tree mechanically, so a rebase or pull request could bring any of them back.

**Approach:** Make the architecture's three closed in-place edits (AD-2) and add the first slice of the offline checker: the `release` static profile, a pure function over a parsed tree, in a new Go `package main` at `scripts/fork-release/`, held by scratch-fixture unit tests. No command surface, git adapter or real-tree test yet. Authoritative wording of the story's criteria: `epics.md`, Story 1.1.

## Design Notes

- **Two-pass YAML (goccy/go-yaml v1.19.2, read from source, not yet run).** The parser rejects true syntactic duplicate keys by key path without expanding aliases (`parser.go` `validateMapKey`); the decoder rejects a merge override as a duplicate for map, `MapSlice` and struct targets (`decode.go` `validateDuplicateKey`, `decodeMap`). Pass 1: `parser.ParseBytes(data, 0)` with default options. It gives the syntax tree, which carries the holds a value tree cannot: more than one document, a merge key that is not first in its mapping, a sequence merge, and duplicates. Pass 2: `yaml.NewDecoder(..., yaml.AllowDuplicateMapKey())` into `any` (first document only), for aliases, merges and typed scalars (`true`/`false` are bool, `no`/`off`/`on` are strings; the option is harmless on pass 2). Resolution applies entries in file order, later wins, which is why a non-first merge key is held. The first tests are the observation of this reading: if the byte-exact `.goreleaser.yaml` or `ci.yml` fixture does not pass both passes, or the library behaves differently from this note, stop and return the difference.
- **Reused anchor names (controller decision, third correction).** Nothing in the frozen matrix or the adopted outcome asks for a name to be given to two anchors in one file; the earlier rebinding rows were controls added by the author. Following the decoder's own nesting and replay of bindings in the syntax tree would be a second implementation of it, so the check holds a name defined twice in one document (`yaml-parse`, "defined more than once") and classifies aliases only against an index in which each name has one node. The price is that a reviewed future file using one label for two anchors is held until it is classified on purpose. Different documents are not affected (a second document is held separately).
- **Templates.** Scan every key and string value for `{{ ... }}`; trim spaces; pass only `.Version`, `.ProjectName`, `.Os`, `.Arch`.
- **Forbidden commands.** Fail-closed over-approximation: split `run` bodies on newlines and shell separators, tokenize on whitespace after stripping quotes, and hold any consecutive-token match of `git push`, `git tag`, `git config user.`, `gh release create|edit|upload|delete`, `curl`, `wget`, `goreleaser release`; for each `gh api`, require exactly one `--method`/`-X` with value `GET`. False positives in echoed text are accepted.
- **Exceptions for `fork-release.yml`, decided here.** Tag-reachable only with exactly `push: tags: ['v*-ezop.*']`; job `release` may hold `contents: write` and nothing else written; `goreleaser-action` may be used only there. A `fork-release.yml` that meets these and the shared rules passes; Story 1.9 adds the rest of the shape (jobs, steps, env pin). The exceptions sit behind one switch because Story 1.2's `mirror` profile allows none.
- **Replacement comment** (wording may vary, content may not): "A release that already exists is never repeated or repaired in place; a repair uses the next version. These two values make GoReleaser refuse to replace an existing asset and keep existing notes if a repeat run ever reaches this step."
- **AQ-2 findings (GoReleaser v2.17.1, literal source; public files `internal/client/github.go` (`Upload`, `createOrUpdateRelease`, `findRelease`, `PublishRelease`), `internal/client/release_notes.go` (`getReleaseNotes`), `pkg/config/config.go` (`Release`), `cmd/config.go` (`loadConfigCheck`), `internal/pipe/git/git.go`).** A 422 on upload with `replace_existing_artifacts: false` returns an unrecoverable error and deletes nothing; `true` deletes the same-named asset and retries. An existing published release is found by tag and updated (name, pre-release flag, body per mode) before any upload. `keep-existing` keeps the existing body only when it is non-empty. `replace_existing_draft` acts only with `draft: true`, so the closed key set never deletes a draft. No contradiction with the spine.
