## Intent

**Problem:** The `release` profile exists only as a function over a tree. The Operator cannot yet ask "is this exact commit safe?" for an `ezop` tip, a `main` tip, an incoming `upstream/main` commit or an Upstream tag tree, and nothing proves that the helper answering is the landed code of this fork.

**Approach:** Add the `mirror` profile (it reads only `.github/`) and the command `fork-release guard --profile release|mirror COMMIT`. The command first checks the helper's own identity (`origin` is `Ezopek/proton-cli`, the binary carries a clean git stamp, its commit is equal to or an ancestor of the `origin/ezop` fetched once at start), then classifies the tree of exactly `COMMIT`, never the working tree, and prints the full SHA it checked. A thin `git` adapter sits under pure checks, and a scratch-repository test proves the documented build recipe stamps. Authoritative wording of the criteria: `epics.md`, Story 1.2.

## Boundaries & Constraints

**Always:**
- `FORK.md` and the accepted spine win. Outside `_bmad-output/`, the change touches only files under `scripts/fork-release/`. No `go.mod` or `go.sum` change (standard library plus the existing `goccy/go-yaml`), nothing under `internal/`, `cmd/` or `tests/`, and `.goreleaser.yaml`, `justfile`, `ci.yml` and both Story 1.1 fixtures stay byte-identical.
- Story 1.1 behavior is kept: `CheckRelease` results do not change, and a reused anchor name stays held. Extending `workflows.go` for `mirror` is allowed; no existing assertion is weakened.
- `mirror` reads only `.github/`. Held-disabled: `release.yml`, `openapi-sync.yml`, `stats.yml`, `web.yml`, any content, but their YAML must parse and no trigger may be tag-reachable (an unreadable one is held). Enabled: `ci.yml`, under the shared rules. Inert: `.github/ISSUE_TEMPLATE/**`. Everything else is held, including `fork-release.yml`.
- Checks are pure functions over plain inputs. Every `git` call goes through one thin adapter behind an interface that tests can replace. Every effective fetch and push URL of `origin` (`git remote get-url --all` with and without `--push`, so `insteadOf` is applied) must be one of the three canonical `Ezopek/proton-cli` forms; no URL, git stderr or other raw diagnostic is ever printed. Any API read names owner and repository as constants, never `GH_REPO`.
- The tree comes from `git ls-tree` and blob reads of the resolved commit. A symlink or submodule entry becomes a non-regular entry in the tree view, which the existing `.github/` rules hold. Every hash-bound git read (resolve, tree, blobs, ancestry) runs with git's own `--no-replace-objects`, so a replacement ref cannot change what a SHA means; blobs are opened only inside the requested profile's paths, and `mirror` never opens `.goreleaser.yaml`. Legacy grafts and adversarial local git metadata are outside the clean-clone promise.
- Every tested `guard` target, ref and git configuration is a scratch one: scratch repositories in `t.TempDir` with their own git configuration and a filtered environment, no network, no real `origin`, no ref or configuration of this repository, no skip. Read-only committed fixtures under `scripts/fork-release/testdata/` and the candidate's own source and module bytes may be copied to build scratch inputs. No test qualifies anything against the real checkout's `.github/`, `.goreleaser.yaml`, refs or network. The raw `v5.1.0` workflow fixture is committed bytes, never read from refs at test time.
- Comments and docs use US spelling and are public-safe. Gates run with the pinned toolchain through the recipes under Verification; never `just test` or any `go test` pattern that can reach `tests/live`.

**Never:**
- No `--pre-push`, in-run guard, tag, record, status, notes, verify, assets or stamp code (Stories 1.3 to 1.8); no `fork-release.yml`; no actual-tree test (Story 1.9); no runbook (Story 1.10).
- No `FORK.md` edit: the wording below travels in the pull request description as a proposal. No faked identity, ancestry or refs in the real repository, no live GitHub or Proton call, no new role, state, lock or recovery protocol, no general workflow analyzer.
- No skipped, weakened or disabled test or gate; no Actions, tag, release, settings or default-branch change.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Release pass | `guard --profile release C`, clean landed helper, `C` is a cleaned fork tree | stdout: `checked <40-hex>` then `release: pass`; exit 0 | N/A |
| Mirror pass | `mirror` on the frozen raw `v5.1.0` workflow tree (incl. `web.yml` with `branches` plus `paths`) | `mirror: pass`; exit 0 | N/A |
| Wrong profile | the same raw tree under `release` | held, naming the four workflow paths; exit 1 | verdict lists each item |
| Mirror holds | new workflow, local action, `dependabot.yml`, `fork-release.yml`, `ci.yml` with a write scope, `secrets.X`, `curl` or unlisted SHA, a held-disabled path with `push` `tags`, unparseable held-disabled file | `mirror: held, N item(s)` with each named; SHA still printed; exit 1 | N/A |
| Commit only | working tree differs from `C`, or `C` is a tag, branch name or `HEAD` | verdict reflects the tree of the resolved commit; the full SHA is printed | unknown revision, non-commit, or an argument starting with `-`: `fork-release: commit: <reason>`, exit 1 |
| Origin wrong | any effective fetch or push URL not canonical, or `origin` missing | refuse before any fetch | `fork-release: origin: <reason>` without the URL, exit 1 |
| Build identity | no build info, no `vcs.revision` or `vcs.modified`, revision not 40 hex, `vcs.modified=true` | refuse | `fork-release: build: <reason>`, exit 1 |
| Landed | helper commit equals or is an ancestor of the fetched `origin/ezop` (ancestry status 0) | proceeds | N/A |
| Not landed | ancestry status 1 | refuse "not landed" | `fork-release: ancestry: ...`, exit 1 |
| Undecidable | ancestry status other than 0 or 1, or the fetch fails | refuse, told apart from "not landed" | `fork-release: ancestry` or `fetch`, exit 1 |
| Usage | missing or unknown profile, no `COMMIT`, extra arguments, other `guard` modes | one-line usage message | exit 2 |
| Stamp proof | scratch repo, documented recipe, clean tree vs. untracked file vs. `-buildvcs=false` | stamped `vcs.revision` with `vcs.modified=false`; the other two are detected as modified or unstamped | N/A |

## Design Notes

- **Why a trigger-only branch.** The architecture says the four paths are held-disabled "with any content": the platform keeps them off, so their enabled-workflow findings are irrelevant, but a tag-reachable trigger could still start them when pushed, so that one rule applies and an unparseable file cannot be judged and is held.
- **Decisions made here, not intent gaps.** Exit codes 0 pass, 1 held or refused, 2 usage. Refusals are one line on stderr; verdicts are stdout. Canonical origin forms are `git@github.com:Ezopek/proton-cli.git`, `https://github.com/Ezopek/proton-cli.git` and `ssh://git@github.com/Ezopek/proton-cli.git`, case-sensitive. `COMMIT` is any revision that peels to a commit. `origin/ezop` is fetched with `git fetch --no-tags origin refs/heads/ezop` and read from `FETCH_HEAD`, with prompts off and a timeout. A tree without `ci.yml` is not held for that. Replace refs are neutralized by `--no-replace-objects` on hash-bound reads; legacy grafts and adversarial local metadata are outside the promise.
- **Consequence to expect.** Until this helper has landed on `origin/ezop`, the real command refuses on ancestry by design (AD-7). Acceptance is offline: fakes, scratch repositories and the scratch build.
- **Proposed `FORK.md` › Following Upstream wording (pull request description only):** "Before `main` is fast-forwarded to an Upstream commit, run `guard --profile mirror <commit>` on that exact commit with a helper built, by the recipe in the runbook, from a landed `ezop` tip. Fast-forward only if it prints that commit's full SHA and reports nothing held. A held item is released only by a reviewed fork change to the classification, never by editing Upstream files. The check reads `.github/` only; it is not a release check."
